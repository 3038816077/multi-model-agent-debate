# 部署指南

> 目标：**换一台机器，20 分钟内跑起来**。本地开发、服务器部署、公网上线都用这一份。

---

## 0. 前置检查（1 分钟）

> 服务器上还没装 Python 依赖也能跑：`.env` 解析是手写的，注册表检查会优雅跳过。

```bash
python scripts/preflight.py
```

它会检查：Python 版本、`.env` 是否齐全、注册表能不能解析、数据目录可写、端口是否被占。
**有任何 ❌ 先修完再往下走**，否则后面报的错都是连锁反应。

---

## 1. 本地跑起来（3 分钟）

```bash
git clone <你的仓库地址>
cd multi-model-agent-debate

# 1) 准备配置：照着模板填 key
cp env.txt .env
#   编辑 .env：OPENAI_API_KEY / MODEL_REGISTRY / API_KEY

# 2) 自检
python scripts/preflight.py

# 3) 启动
python run.py            # 或 uvicorn app.main:app --port 8000
```

打开 <http://127.0.0.1:8000>。

**成功标志**：

```bash
curl -s localhost:8000/health | python -m json.tool
# {"status":"ok","models":5,...,"problems":[]}
```

`status` 不是 `ok` 时，看 `problems` 里每条的中文说明。

---

## 2. Docker 方式（可选，5 分钟）

```bash
docker compose up -d --build
docker compose ps                  # 等 STATUS 变成 healthy
curl -s localhost:8000/health
```

**常见坑：容器里下不了模型**（HF 直连不稳）。宿主机跑过本项目的话，缓存已经在了：

```bash
# .env 里加一行（Windows 路径用正斜杠）
HF_CACHE=C:/Users/你的用户名/.cache/huggingface
```

## 3. 部署到服务器（15 分钟）

### 3.1 系统准备

```bash
# Ubuntu 22.04 为例
apt update && apt install -y python3.10 python3-pip git docker.io docker-compose-plugin
```

1 核 2G 起（模型推理在远端，本地只做编排，内存主要给 embedding/rerank）。

### 3.2 拉代码 + 配置

```bash
git clone <仓库地址> /opt/mma && cd /opt/mma
cp env.txt .env
vim .env          # 填 key；SERVER_PORT=8000
python3 scripts/preflight.py
```

### 3.3 启动（二选一）

**A. Docker（推荐）**

```bash
docker compose up -d --build
```

**B. systemd（不用 Docker）**

```ini
# /etc/systemd/system/mma.service
[Unit]
Description=Multi-Model Agent
After=network.target

[Service]
WorkingDirectory=/opt/mma
Environment=PYTHONUNBUFFERED=1
ExecStart=/usr/bin/python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now mma
systemctl status mma
```

### 3.4 反向代理 + HTTPS

**Caddy（最简单，自动申请证书）**

```
# /etc/caddy/Caddyfile
你的域名.com {
    reverse_proxy 127.0.0.1:8000 {
        flush_interval -1
    }
}
```

```bash
apt install -y caddy && systemctl reload caddy
```

**Nginx**

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名.com;
    ssl_certificate     /etc/letsencrypt/live/你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # SSE 关键三行
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}
```

> **不关缓冲的话，流式输出会一次性蹦出来**，看起来像卡死。

## 3.5 阿里云 ECS 特别注意

### 域名与备案

**内地地域的 ECS，用域名走 80/443 必须有 ICP 备案**，否则会被拦截。没有备案时：

```
方案 A  直接用 http://公网IP:8000 演示（最快，面试够用）
方案 B  买香港/新加坡地域（免备案，但延迟高）
方案 C  先备案（2~3 周），再上域名
```

### 安全组

阿里云控制台 → 安全组 → 入方向，至少放行：

| 端口 | 用途 |
| --- | --- |
| 22 | SSH |
| 8000 | 应用直连（没有域名时用这个） |
| 80 / 443 | 域名访问（需备案） |

### 从服务器拉 GitHub 慢

内地服务器直连 GitHub 常常只有几十 KB/s。两个替代方案：

```bash
# 方案 A：用代理前缀（第三方，稳定性看运气）
git clone https://ghproxy.net/https://github.com/你的账号/multi-model-agent-debate.git

# 方案 B：本地打包上传（最稳）
# 本地执行：
git archive --format=tar.gz -o mma.tar.gz HEAD
scp mma.tar.gz root@服务器IP:/opt/
# 服务器执行：
mkdir -p /opt/mma && tar -xzf /opt/mma.tar.gz -C /opt/mma
```

> `.env` 永远不要走 git，在服务器上手动创建。

### 内存

1 核 1G 会在加载 embedding 模型时 OOM。**最低 1 核 2G**，或者加 swap：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 一键脚本

```bash
cd /opt/mma
cp env.txt .env && vim .env
bash scripts/deploy_ecs.sh
```

脚本会：装 docker → 检查占位符 → 校验 compose → 构建启动 → 等 healthy → 打印公网地址。

## 3.6 2 核 2G 内地机器：照着这条走

### 先看磁盘（构建镜像要 20G 以上）

```bash
df -h /        # 可用空间 < 15G 就先清理，镜像 6.6G + 构建缓存
free -h        # 确认内存 2G
```

### 加 2G swap（防 OOM）

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h        # 应该看到 Swap: 2.0Gi
```

> 加载 embedding + reranker 时内存会冲高，2G 物理内存没有 swap 容易被杀进程。

### 配 Docker 镜像加速（内地必做）

内地直连 Docker Hub 拉 `python:3.10-slim` 经常几分钟没动静。用阿里云的加速器：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://<你的专属加速地址>.mirror.aliyuncs.com"]
}
EOF
systemctl daemon-reload && systemctl restart docker
```

加速地址在：阿里云控制台 → 容器镜像服务 → 镜像工具 → 镜像加速器。

### 然后执行

```bash
cd /opt/mma
cp env.txt .env && vim .env      # 填 key
bash scripts/deploy_ecs.sh
```

### 安全组放行

控制台 → 安全组 → 入方向 → 添加 `8000/8000`，授权对象 `0.0.0.0/0`。

### 验收

手机流量（关 Wi-Fi）打开 `http://你的公网IP:8000`，能看到界面就成功。

```bash
# 服务器上也可以自测
curl -s localhost:8000/health
curl -s localhost:8000/metrics | head -5
```

## 3.7 机器上已经有别的服务（端口冲突）

先摸清现状：

```bash
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
ss -lntp | grep -E ':8000|:80'
df -h /
free -h
```

如果 8000 被旧项目占着，二选一：

```bash
# A. 停掉旧的（推荐，避免两份数据/两个后台）
cd /opt/老项目 && docker compose down

# B. 给新项目换个端口，在 .env 里加：
APP_PORT=8080
SERVER_PORT=8080
```

> 两个端口要一起改：`SERVER_PORT` 是容器内监听端口，`APP_PORT` 是宿主机映射端口。
> 只改一个会导致容器在听 A、映射到 B，访问不通。

## 4. 上线前必须做的四件事

### 4.1 换个 API_KEY

```bash
# .env 里默认是 my-secret-key-123，必须改
API_KEY=<随机字符串>
```

### 4.2 限制 /metrics 和 /health 的来源

这两个端点不带鉴权（给 Prometheus 和负载均衡用）。公网部署时：

```nginx
location = /metrics {
    allow 127.0.0.1;
    deny all;
    proxy_pass http://127.0.0.1:8000;
}
```

### 4.3 加访问密码（挡住爬虫和路人）

Caddy 用 `basicauth`，Nginx 用 `auth_basic` + `htpasswd`。

### 4.4 设预算上限

模型按量计费，公开接口会被刷。至少做一层：

- 每 IP 每分钟请求数限制（SlowAPI 已内置，`RATE_LIMIT_ENABLED=1`）
- 供应商后台设每日消费上限
- 打开应用层每日额度（默认关闭，公网必开）：

```bash
DAILY_QUOTA_ENABLED=1
DAILY_QUOTA_PER_IP=30     # 每 IP 每天可调用次数
DAILY_QUOTA_GLOBAL=300    # 全局每天上限
TRUST_PROXY=0             # 挂在 Nginx/Caddy 后面时改成 1
```

> 超限返回 429 并带 `X-Quota-Remaining`；持有 `API_KEY` 的请求不计数（自己调试用）。

| 事项 | 命令 / 位置 |

| 备份数据库 | `python scripts/backup_db.py`（建议 cron 每天一次） |

| 单实例约束 | 同一 `data/` 目录只能起一个进程（有锁保护） |

## 6. 排错速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报「另一个实例正在使用同一个 data 目录」 | 已有进程在跑 | `pkill -f uvicorn` 或换目录 |
| `/health` 返回 503 | 注册表为空 / 目录不可写 | 看 `problems` 字段 |
| 对话报「请求超时」 | 模型慢或超时太短 | 调大 `.env` 的 `LLM_TIMEOUT` |
| 容器起来但连不上模型 | 容器网络 / key | `docker compose logs -f` 看具体错误 |
| 流式输出卡住不吐字 | 反代开了缓冲 | 关 `proxy_buffering` |
| `database is locked` | 两个进程抢同一个库 | 只留一个实例 |

```
□ 服务器 1 核 2G
□ git clone + cp env.txt .env + 填 key
□ python scripts/preflight.py 全绿
□ docker compose up -d --build（或 systemd）
□ curl /health 返回 ok
□ Caddy/Nginx 反代 + HTTPS
□ 关掉反代缓冲（SSE 必须）
□ 改 API_KEY + 加 Basic Auth
□ /metrics 限制为内网
□ 供应商后台设预算上限
□ cron 每天跑备份
□ 挂上 Prometheus 抓取
```
