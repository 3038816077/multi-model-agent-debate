# ADR-0003：分歧分析的降级链——宁可用贵的，也不要掉到最弱档

- 状态：已采纳
- 日期：2026-11-18
- 相关：`app/api/chat.py` 的 `analyze_divergence`、`app/core/router.py`

## 背景

最初的分歧分析在裁判模型失败时，直接退到「最便宜档」（GLM-4-Flash）。
实测踩坑：DeepSeek V4 Pro 超时后掉到 GLM-4-Flash，它把四份结论一致的答案
拆成两组「分歧」，报告整体不可信。

## 决定

降级顺序改为：**主模型 → 强模型 → 便宜模型**，并给裁判单独放宽超时（150s）。

## 理由

- 分歧分析是并行模式的**唯一产出**，质量权重远高于成本
- 便宜档模型在这项任务上实测误报率 100%（22 组评测）
- 裁判调用只占单次对话成本的一小部分（一次并行里 1/4 左右）

## 后果

- 主模型不可用时，报告慢一些、贵一些，但不会静默变差
- 分层路由里的 `TIER_STRONG` 必须有至少一个可用模型，否则会退到 cheap
  （启动自检会提示 `tier_no_match`）
