# 我给多模型并行做了四轮评测，结论是：它赢不了单模型

> 一个真实项目的评测返工记录：三次数字是假的，第四次才敢用。

![封面](封面-多模型并行赢不了单模型.png)

---

## 先说结论

我做了一个多模型并行对话系统：多个模型各自回答同一个问题，然后由裁判模型产出一份「共识 + 分歧」报告。

做完之后我理所当然地以为它比单模型强。评测跑完，四轮，最后一轮的结果是：

| 模式 | 均分 | 平均耗时 |
| --- | --- | --- |
| 单模型（Kimi K3） | **9.60** | 51 秒 |
| 并行（Kimi K3 + DeepSeek V4 Pro） | **8.50** | 105 秒 |

差值 1.10，95% 置信区间 [0.60, 1.60]，20 题里**并行赢 3 题、输 17 题**。

**它确实更差，而且慢一倍。** 但我还是把它留着了——原因在后面。

---

## 我做的到底是什么

不是「让多个模型投票」，而是：

1. 多个模型**独立**回答（互相看不到）
2. 裁判模型读所有回答，输出结构化 JSON：`共识` / `分歧` / `孤例`
3. 分歧必须附**逐字引文**，再用代码在原文里回查，核对不上就降级成「未核实的分歧」

第 3 步很关键。最初裁判会**编造引文**——声称「回答说 X」，但原文里根本没这句。

所以加了接地校验：

```python
def verify_quote(quote: str, source: str, min_chars: int = 10) -> bool:
    q = normalize(quote)      # 去标点、去空白
    s = normalize(source)
    if len(q) < min_chars:
        return False
    if q in s:
        return True
    # 允许两成字符被改动（模型引用时常改标点、删虚词）
    matched = sum(b.size for b in SequenceMatcher(None, q, s).get_matching_blocks())
    return matched >= 0.8 * len(q)
```

核对不上的分歧不会被丢掉，而是换一个标题展示——**「没核对上」和「没有分歧」是两件事**。

## 第一轮：数字是假的（三次）

### 第一次：测出来的不是模型，是限流

首轮跑 22 组分歧评测，结果：

```
kimi-k3.1-pro    准确率 45.5%   检出 0%
glm-4.6          准确率 36.4%
```

看起来结论是「这两个模型做不了这件事」。翻原始输出才发现：

```
kimi   → 输出全是空字符串
glm-4.6 → 22 题里 14 题 "429 您的账户已达到速率限制"
```

**两个原因：**

- 思考型模型给了 `max_tokens=800`，全被推理吃掉，正文为空；空正文又被当成「判定无分歧」记成漏报
- 并发 4 触发 429，失败直接被算成答错

修完重跑：

```
kimi     45.5% → 100%
glm-4.6  36.4%（14 题失败）→ 95.5%（0 失败）
```

**同一个题集，同一个模型，差了 55 个百分点。**

### 第二次：超时被当成答错

换到答案质量评测，单模型臂 20 题里有 6 题得分 0~1 分。看原始回答：

```
q09 单=0.0  "模型 kimi-k3 请求超时，检查网络或调大 .env 里的 LLM_TIMEOUT"
q11 单=1.0  同上
```

90 秒超时对思考型模型根本不够。这份均分 6.17 完全是假的。

### 第三次：并行臂 0 秒返回，全部 0 分

这次更隐蔽：并行臂每一题都是 0.0~1.0 分，耗时 0.0 秒。

原因是接口有个校验——**主模型不能和副模型重复**，而我把 `--chief` 和 `--staff` 里放了同一个模型。接口直接拒绝，评测脚本把错误文本当成答案喂给了裁判。

---

## 第四轮：才敢用的那个数字

这次把三个坑都补上（重试 + 空输出检测 + 主副模型去重），并且把阵容换成两个强模型：

| 项 | 配置 |
| --- | --- |
| 单模型臂 | Kimi K3 |
| 并行臂 | Kimi K3 + DeepSeek V4 Pro（**包含**单模型臂的模型） |
| 裁判 | GLM-4.6，不在任一臂内 |
| 超时 / 并发 | 240s / 3 |

结果就是开头那张表：**9.60 vs 8.50**。

上一轮并行臂里混了个免费小模型（GLM-4-Flash），差距是 3.30；换成强模型后差距缩到 1.10。**所以「输在弱模型」占了大头。**

---

## 剩下那 1.10 分，输在哪

我把裁判的打分理由逐条看了，发现了很一致的模式：

**20 题里有 17 题，裁判明确提到「重复」或「拼接」。**

裁判原话：

> q03：内容正确且可执行，但由两份模型回答拼接，有明显重复，根据规则扣 1 分

原因很直白：

```
单模型臂：一份答案
并行臂：  两份完整答案首尾相接 + 一份分歧报告
```

读者要读两遍相似内容。裁判按「可读性 / 无冗余」打分，自然扣分。

**这不是模型不会答，是输出形态不适合直接读。**

## 那它到底有什么用

如果我继续用「答案质量」这一把尺子，并行模式永远输。所以我换了个问法：

**分歧分析本身准不准？**

22 组人工标注的样本（12 组真冲突、10 组无冲突），5 个模型分别当裁判：

| 模型 | 准确率 | 检出 | 引文已核实 | 误报 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| Kimi K3.1 Pro | **100%** | 100% | 100% | 0% | 32s |
| DeepSeek V4 Flash | 95.5% | 91.7% | 91.7% | 0% | 32s |
| GLM-4.6 | 95.5% | 100% | 100% | 10% | 37s |
| GLM-4-Flash | 50.0% | 91.7% | 66.7% | **100%** | 8.5s |

两个结论：

1. **强模型做分歧分析已经很可靠**（95%~100%，误报 0%）。
2. **弱模型绝对不能进阵容**：GLM-4-Flash 把 10 组无冲突样本**全部**编出了分歧，误报率 100%。它便宜，但它的存在会让整份报告不可信。

所以现在的定位是：

> 并行模式不是「更好的问答」，是**「决策辅助 / 交叉验证」**。
> 它的产出是「这两个模型哪里不一致」，而不是「一段更好的文字」。

## 顺手留下的工程资产

评测返工逼出来一堆东西，比功能本身更有价值：

**1. 37 个离线测试**（不调模型、不花钱）

```
test_divergence.py      编造引文必须降级；同立场必须合并成一组
test_doc_reader.py      PPTX 页码排序（slide2 不能排在 slide10 后）
test_model_config.py    分层路由引用的模型必须真在注册表里
test_selfcheck.py       配置问题要在启动时说，别运行时才 500
test_benchmark_grading  评分逻辑本身也要有测试
```

最后一条是血泪：我改渲染器让「无分歧」也输出 `**分歧**` 标题，评分代码只看标题就判定「编造了分歧」——**每道无冲突题都被算成误报**。评分代码错了，比模型错了更可怕。

**2. 启动自检 + /health**

```json
{"status":"ok","models":4,"problems":[]}
```

注册表为空、分层引用了已删除的模型、目录不可写——这些以前要等用户点发送才 500，现在启动就报，`/health` 返回 503。

**3. 三篇 ADR**（记录「不做什么」和「为什么」）

包括被否掉的方案：给分歧分析加一层 LLM 复核后，**误报归零，但真分歧也杀掉一半**（检出 91.7% → 67%）。所以复核默认关闭。

---

## 给做类似项目的人三条建议

**1. 评测脚本要先自测。**
空输出、429、超时、参数冲突——每一种都会让结论反向。我四轮里三轮是假数字。

**2. 别用「答案质量」评价多模型系统。**
它的价值在于「发现分歧」，用可读性打分它必输。想清楚你要证明什么，再选指标。

**3. 弱模型进阵容是负收益。**
成本涨、分数降、报告还不可信。宁可两个强的，不要三个凑数的。

---

## 最后

这个项目最初的目标是「证明多模型比单模型强」。

四轮评测之后，我得到的结论是：**在「直接读一份答案」这件事上，它不会更强；但在「知道谁在哪里不同意」这件事上，它提供了单模型给不了的信息。**

承认前者，才能把后者做扎实。
